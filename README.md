# MAISON ORÉE 웹사이트 (Pages CMS 연결판)

운영자가 코드 없이 **글, 사진, 교육 프로그램(클래스), 제작 실적, 상품**을 추가하고 고칠 수 있는 사이트입니다.
내용은 `content/` 폴더의 JSON 파일에 있고, 운영자는 Pages CMS 관리 화면에서 이 파일을 편집합니다.
저장하면 GitHub에 기록되고, 1~2분 뒤 사이트에 반영됩니다.

## 폴더 구성

| 경로 | 내용 | 누가 고치나 |
| --- | --- | --- |
| `index.html` | 화면 틀과 디자인 | 개발 담당 |
| `js/site.js` | JSON을 읽어 화면을 그리는 코드 | 개발 담당 |
| `js/purify.min.js` | 저널 본문을 안전하게 표시하는 라이브러리 (DOMPurify 3.1.6, 라이선스 `js/purify.LICENSE.txt`) | 고치지 않음 |
| `.pages.yml` | Pages CMS 관리 화면의 메뉴와 입력칸 설정 | 개발 담당 |
| `apps-script/Code.gs` | 상담 폼 수신기 (구글 스프레드시트에 붙여 넣는 코드, 사이트에 올릴 필요 없음) | 처음 한 번 설치 |
| `content/site.json` | 메인 문구, 대표 사진, 카테고리, 아틀리에 소개, 연락처 | 운영자 (CMS) |
| `content/products.json` | 상품 | 운영자 (CMS) |
| `content/programs.json` | 교육 프로그램 (클래스) | 운영자 (CMS) |
| `content/portfolio.json` | 제작 실적 | 운영자 (CMS) |
| `content/journal.json` | 저널 글 | 운영자 (CMS) |
| `images/` | 사진. CMS로 올린 사진은 `images/uploads/`에 저장 | 운영자 (CMS) |

## 1. 처음 한 번: GitHub에 올리고 사이트 열기

1. [github.com](https://github.com)에 가입하고 로그인합니다.
2. 오른쪽 위 **+ → New repository**를 누릅니다. 이름은 `maison-oree`, 공개 범위는 **Public**으로 만듭니다.
   (무료 계정에서 GitHub Pages로 사이트를 열려면 Public 저장소가 필요합니다.)
3. 새 저장소 화면에서 **uploading an existing file**을 눌러 이 폴더 안의 파일과 폴더를 모두 끌어다 놓고 **Commit changes**를 누릅니다.
   - `.pages.yml`은 이름이 점(.)으로 시작해 탐색기에서 숨겨질 수 있습니다. 업로드 목록에 들어갔는지 꼭 확인하세요.
     (Windows 탐색기: 보기 → 표시 → 숨긴 항목 체크)
4. 저장소의 **Settings → Pages**에서 Source를 **Deploy from a branch**, Branch를 **main / (root)**로 고르고 **Save**를 누릅니다.
5. 1~2분 뒤 같은 화면 위쪽에 사이트 주소(`https://아이디.github.io/maison-oree/`)가 나타납니다.

> Netlify, Vercel, Cloudflare Pages에 GitHub 저장소를 연결해도 똑같이 동작합니다. 빌드 명령은 비워 두고, 공개 폴더는 저장소 최상위로 지정하세요.

## 2. Pages CMS 연결

1. [app.pagescms.org](https://app.pagescms.org)에 들어가 **GitHub로 로그인**합니다.
2. 안내에 따라 **GitHub App을 설치**하고 `maison-oree` 저장소에 접근을 허용합니다.
3. 저장소를 열면 왼쪽에 메뉴 다섯 개가 보입니다: 교육 프로그램, 제작 실적, 저널, 상품, 사이트 문구와 사진.
   (`.pages.yml`이 이미 들어 있어 따로 설정할 것이 없습니다.)
4. GitHub 계정이 없는 직원은 Pages CMS의 **협업자(Collaborators) 초대**로 이메일 초대할 수 있습니다.
   초대받은 사람은 내용과 사진만 편집할 수 있고, 설정 파일은 바꿀 수 없습니다.

## 3. 운영 방법

| 메뉴 | 할 수 있는 일 | 사이트에서 보이는 방식 |
| --- | --- | --- |
| 교육 프로그램 | 클래스 추가, 날짜·가격·정원·상태 변경, 신청 링크 입력 | 날짜가 가까운 순. **지난 날짜는 자동으로 숨김**. 상태가 '마감'·'오픈 예정'이면 신청 버튼이 꺼짐 |
| 제작 실적 | 실적 추가, 사진·분류·새긴 문구 입력 | '맨 앞에 보이기'를 켠 항목이 먼저, 나머지는 최신순. 처음 6개만 보이고 '더 보기'로 펼침. 분류 버튼은 쓰인 분류만 자동 표시 |
| 저널 (글) | 글 쓰기, 사진 넣기, 공개/비공개 | '사이트에 공개'가 켜진 글 중 최신 3개. 누르면 본문이 창으로 열림 |
| 상품 | 상품 추가, 가격, 품절, 베스트셀러 표시 | '베스트셀러에 보이기'를 켠 상품이 '전체' 탭에 보임 |
| 사이트 문구와 사진 | 메인 제목·사진, 카테고리, 아틀리에 소개, 기프트 소개, 서비스 띠, 연락처, 상담 폼 설정(수신 주소, 문의 유형, 동의 문구) | 각 칸이 해당 위치에 바로 반영. 제목은 Enter로 줄을 바꿀 수 있음 |

- **저장** 버튼을 누르면 GitHub에 저장되고, 1~2분 뒤 사이트를 새로고침하면 반영됩니다.
- 상품, 카테고리, 서비스 띠는 관리 화면의 목록 순서대로 보입니다. 교육 프로그램, 저널, 제작 실적은 날짜 기준으로 자동 정렬됩니다.
- 링크 칸에는 `https://`로 시작하는 주소나, 페이지 안 위치(`#programs`, `#contact` 등)를 넣습니다.

### 사진 규칙

- 형식: JPG, PNG, WebP (WebP 권장)
- 크기: 메인 사진은 가로 1920px 이상, 나머지는 긴 변 1600px 정도. 한 장 500KB 이하가 좋습니다.
- 비율: 상품·클래스 4:5(세로), 제작 실적 1:1(정사각형), 저널 4:3(가로)
- 사진마다 **사진 설명** 칸을 채워 주세요. 화면 낭독기를 쓰는 분과 검색엔진이 읽습니다.

## 4. 상담 폼 수신 연결 (구글 스프레드시트 + 이메일 알림)

홈페이지의 **기업·단체 상담** 폼으로 들어온 문의는 운영자 구글 계정의 스프레드시트에 한 줄씩 쌓이고, 지정한 이메일로 알림이 갑니다.
별도 유료 서비스는 필요 없습니다. 처음 한 번, 15분 정도 걸립니다.

1. [sheets.new](https://sheets.new)로 새 스프레드시트를 만들고 이름을 `MAISON ORÉE 상담 문의`로 바꿉니다.
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 편집기에 있던 코드를 모두 지우고, 이 폴더의 `apps-script/Code.gs` 내용을 통째로 붙여 넣습니다.
4. 맨 위 설정을 바꿉니다.
   - `NOTIFY_EMAIL`: 알림 받을 이메일 (여러 명이면 쉼표로 구분)
   - `RETENTION_DAYS`: 보관 기간(일). 동의서의 「보유·이용 기간」과 같아야 합니다. 기본 365일
5. 저장(디스크 아이콘)한 뒤, 위쪽 함수 선택에서 **setup**을 고르고 **실행**을 누릅니다.
   권한 요청 창이 뜨면 본인 계정으로 허용합니다. ('확인되지 않은 앱' 경고가 나오면 고급 → 이동을 누릅니다. 본인이 만든 스크립트라 안전합니다.)
   → `상담 문의` 시트가 생기고, 보관 기간이 지난 문의를 매일 새벽 3시에 지우는 예약이 등록됩니다.
6. 오른쪽 위 **배포 → 새 배포**를 누릅니다.
   - 유형 선택: **웹 앱**
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
   - **배포**를 누르고 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
7. Pages CMS → **사이트 문구와 사진 → 기업·단체 상담 폼 → 수신 주소**에 URL을 붙여 넣고 저장합니다.
8. 1~2분 뒤 사이트에서 직접 테스트 문의를 보내 보세요. 시트에 한 줄이 생기고 알림 메일이 오면 연결 완료입니다.

알아둘 점

- 수신 주소가 비어 있으면 폼은 제출되지 않고, 방문자에게 전화·이메일로 연락하라는 안내가 나옵니다. (사이트 문구 → 연락처를 채워 두세요.)
- 스크립트를 고친 뒤에는 **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포**로 다시 배포해야 반영됩니다. 이때 URL은 그대로입니다.
- 개인 Gmail 계정은 스크립트가 하루에 메일을 보낼 수 있는 수신자 수가 100명으로 제한됩니다. 한도를 넘으면 알림 메일만 건너뛰고 시트 저장은 정상적으로 됩니다.
- 스팸 방지: 사람에게 보이지 않는 함정 칸, 3초 안에 제출된 요청 무시, 같은 연락처는 1분에 한 번, 전체 1분에 20건 제한이 들어 있습니다.
- 시트의 **처리 상태**와 **메모** 칸은 운영자가 자유롭게 쓰는 칸입니다. (예: 접수 → 견적 발송 → 완료)
- 문의 데이터가 구글 서버에 저장되므로, 개인정보처리방침에 '개인정보 처리 위탁: Google LLC (상담 문의 저장)' 같은 내용을 함께 적어 두세요. 동의 문구와 처리방침은 공개 전에 전문가 검토를 받는 것을 권합니다.

## 5. 공개 전에 꼭 바꿀 것

- [ ] 교육 프로그램, 제작 실적, 저널의 **"예시:"로 시작하는 항목**을 실제 내용으로 바꾸거나 삭제
- [ ] 제작 실적의 고객사 이름은 **공개 동의를 받은 경우만** 입력
- [ ] 사이트 문구 → 연락처: 주소, 이메일, 전화, 카카오톡 채널, 인스타그램 링크
- [ ] 사이트 문구 → 사업자 정보 (상호, 대표자, 사업자등록번호, 통신판매업 신고번호 등)
- [ ] 아틀리에 소개의 숫자(연소 시간, 숙성 기간)를 실제 값으로 확인
- [ ] 클래스 신청 링크 (네이버 예약 등). 비워 두면 기업·단체 상담 폼으로 이동하고 문의 내용이 미리 채워집니다
- [ ] 상담 폼 수신 주소 연결 (4장) 후 테스트 문의 1건 보내기

## 6. 컴퓨터에서 미리 보기

`index.html`을 더블클릭해 열면 브라우저 보안 때문에 JSON을 읽지 못해 내용이 비어 보입니다.
이 폴더에서 아래 중 하나로 열어 주세요.

- VS Code의 **Live Server** 확장 → `index.html` 오른쪽 클릭 → Open with Live Server
- 터미널에서 `python -m http.server 8000` 실행 후 `http://localhost:8000` 접속

## 7. 알아둘 점

- 상담 폼은 실제로 접수됩니다(4장 연결 후). 장바구니, 위시리스트, 뉴스레터 구독은 화면에서만 동작합니다. 실제 결제·구독을 받으려면 스마트스토어 링크나 메일 서비스(스티비, 메일침프 등)를 연결해야 합니다.
- 내용은 페이지가 열릴 때 불러옵니다. 구글은 이런 페이지도 읽지만, 네이버 검색 노출이 중요해지면 빌드 단계(예: Eleventy)를 추가해 HTML로 미리 만들어 두는 방식을 권합니다.
- `content/*.json`을 GitHub에서 직접 고칠 때 쉼표나 따옴표가 빠지면 해당 영역이 비고, 페이지 위에 안내 문구가 나타납니다. 가능하면 Pages CMS 화면에서 편집하세요.
